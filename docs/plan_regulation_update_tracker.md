# 메일 분석 — 규정/준칙 업데이트 요청 이행 추적 (계획)

## 목표
메일 분석 메뉴에서, **규정·준칙 업데이트를 요청하는 메일**을 찾아 각 메일의 처리 상태를
판정하고, **결과적으로 업데이트가 수행되지 않은(미이행) 요청만** 골라낸다.

판정 트리:
```
업데이트 요청 메일?
 ├─ 아니오 → 제외
 └─ 예 → 내가 회신했나?
          ├─ 미회신           → ★ 미이행 (후속 필요)
          └─ 회신함 → 회신 내용은?
                       ├─ "업데이트 완료" 회신   → 이행 (제외)
                       └─ "추가 확인 필요" 회신   → ★ 미이행 (후속 필요)
```
최종 산출: **★ 미이행 목록**(미회신 + 추가확인필요). 각 항목은 원문 메일을 바로 열 수 있는 링크 포함.

## 데이터 소스 / 전제
- 메일은 **사용자 PC 로컬 브릿지**(`outlook_bridge.exe`)를 통해 조회(본인 Outlook). 서버 배포 구조 대응.
- 회신 여부는 두 신호를 병행:
  1. **`reply_status`** — `PR_LAST_VERB_EXECUTED`(수신 메일에서 내가 회신/전달했는지, 이미 구현됨).
  2. **스레드 매칭** — `ConversationID`로 같은 대화의 **보낸 메일(내 회신)** 을 찾아 회신 본문을 확보
     (완료/추가확인 분류에 필요). ※ get_emails 는 수신함(6)+보낸편지함(5)을 모두 읽으므로 가능.

## 필요한 배관 추가
1. **`outlook_agent.get_emails` 반환에 `conversation_id` 추가** (`item.ConversationID`).
   - 브릿지 `/emails` 는 그대로 전달(스키마만 확장).
2. (선택) 브릿지 **`/open-email`** 엔드포인트 — `outlook_agent.open_email(entry_id, store_id)` 로 원문을 Outlook에서 열기.
   - 메일 분석 목록의 "원문 열기" 버튼이 브릿지 POST 로 호출. (#1 에서 만들 브릿지 열기 기능과 공유)

## 처리 파이프라인 (서버측, LLM)
1. **조회**: 기간(시작~종료) + 옵션 발신자/키워드 → 브릿지로 수신·발신 메일 로드.
2. **요청 메일 식별**: 각 수신 메일을 LLM 분류
   - 1차 키워드 프리필터(규정, 준칙, 지침, 세칙, 개정, 제·개정, 업데이트, update, revise, 반영) 로 후보 축소(비용↓)
   - 2차 LLM 판정: "이 메일이 규정/준칙 업데이트를 **요청**하는가?" (yes/no + 근거 1줄)
3. **회신 매칭**: 후보별 `conversation_id`로 **내가 보낸 회신**(발신함, 요청메일 이후 시각) 검색.
   - 없고 `reply_status`도 비어있음 → **미회신**.
   - 있으면 가장 최근 내 회신 본문을 회신 텍스트로 사용.
4. **회신 유형 분류**(회신 있을 때만): LLM
   - "이 회신이 (A) 업데이트 완료 통보인가, (B) 추가 확인·보류·질문인가?" → {완료 | 추가확인} + 근거.
5. **결론 집계**: 미회신 또는 추가확인 → **미이행**. 완료 → 이행(제외).

## UI (메일 분석 메뉴)
- 새 탭/모드 **"규정 업데이트 추적"** 추가(기존 조회/분석/회신 초안 옆).
- 입력: 기간(시작~종료), (선택) 발신자/키워드.
- 실행 시: 진행 로그(후보 N건 → 요청 M건 → 회신 매칭 → 분류) + **취소 버튼**(기존 취소 패턴 재사용).
- 결과 표: | 요청 메일(제목/발신/일자) | 회신여부 | 회신유형 | **결론(미이행 강조)** | 원문 열기 |
  - 기본은 **미이행만** 표시, 토글로 전체 보기.
- LLM 호출량이 많으므로(메일당 1~2회) 후보 프리필터 + 진행률 + 취소 필수.

## 정확도/한계 (사전 고지)
- **회신 여부**: 다른 사람이 대신 회신했거나, 회신을 Outlook 밖(구두/타 시스템)에서 처리한 경우는 감지 불가.
- **완료/추가확인 분류**: 회신 문구가 모호하면 오분류 가능 → 근거 문장을 함께 표시해 사용자가 검증.
- **스레드 매칭**: `ConversationID`가 끊긴(제목 변경·포워드) 경우 누락 가능 → 제목(RE:) 보조 매칭 고려.
- 은행 업무 특성상 **"미이행 후보"는 사람이 최종 확인**하는 보조 도구로 포지셔닝(자동 단정 금지).

## 수정 파일(예정)
- `src/outlook_agent.py` — get_emails 에 `conversation_id` 추가; (open_email 재사용)
- `bridge/outlook_bridge.py` — `/open-email` 추가(선택), `/emails` 스키마 확장 반영(자동)
- `src/outlook_panel.py` — "규정 업데이트 추적" 탭 UI + 파이프라인 호출 + 결과표/링크
- 신규 `src/regulation_tracker.py`(선택) — 식별·분류·집계 로직(LLM 프롬프트 포함) 분리

## 확인 필요 (진행 전)
1. **요청 식별 방식**: 키워드 프리필터 + LLM 2차(권장) vs 순수 LLM(느리지만 폭넓음).
2. **"미이행" 정의**: (미회신 + 추가확인) = 미이행 (제안) 이 맞는지.
3. **회신 주체**: "내(로그인 사용자) 회신"만 볼지, 팀 공유메일함 등 타인 회신도 포함할지.
4. **기간 기본값**: 예) 최근 90일.
